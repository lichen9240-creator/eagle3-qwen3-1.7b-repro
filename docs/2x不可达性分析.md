# EAGLE-3 加速比上限的数学分析：为什么 2x 不可达

> 基于本机两轮实测（v1: 21,750 条；v2: 41,405 条），同一张 4090-48G、同一套 config、同一 benchmark。
> 本文不是"感觉做不到"，而是把加速比拆成可测的量，反解出唯一的自由参数，再证明要达到 2x 需要什么条件、以及那个条件离现实有多远。

---

## 0. 实测数据

| | v1 | v2 |
|---|---|---|
| 训练数据 | 21,750 | 41,405 |
| acceptance τ (C=1) | 2.090 | 2.268 |
| 吞吐 baseline → EAGLE | 230.4 → 256.9 | 234.0 → 283.6 |
| speedup S | 1.115x | 1.212x |
| TPOT baseline → EAGLE | 4.22 → 3.80 ms | 4.18 → 3.44 ms |

---

## 1. 把加速比拆成三个可测量

一次「验证循环」产出 τ 个 token，耗时 = 验证一次（4 个位置）+ 3 次 draft 前向。

```
S = τ / O          ……(1)
                  O = 每轮耗时 ÷ 单 token 耗时
```

用实测反解 O：

| | τ | S | O = τ/S |
|---|---|---|---|
| v1 C=1 | 2.090 | 1.115 | **1.874** |
| v2 C=1 | 2.268 | 1.212 | **1.871** |
| v2 C=4 | 2.255 | 1.207 | **1.868** |
| v2 C=8 | 2.256 | 1.190 | **1.896** |

**四组独立测量，O = 1.87 ± 0.02。** 这个量只由"验证 4 个位置 + 3 步 draft"的硬件代价决定，与训练数据量、与并发度都无关。

---

## 2. 关键一步：O 对 draft 步数 k 的斜率是**参数无关**的

设单 token 前向代价 `c(1) = a + b`，其中 a 为固定开销（权重读取），b 为 per-token 计算；
验证 k+1 个位置代价 `c(k+1) = a + b(k+1)`；一次 draft 前向代价 `d = δ·c(1)`。

```
O(k) = [c(k+1) + k·d] / c(1) = 1 + k·[(1-r) + δ]，   r = a/(a+b)
```

于是 `O(k) - 1` 对 k 是线性的，斜率 `s = (1-r) + δ` 与 r、δ 怎么拆分无关。
用「k=0 时 O=1」和「k=3 时 O=1.87」两个点定出：

```
O(k) = 1 + 0.29·k        ……(2)
```

**这是一个不含任何可调参数的式子**——(1-r) 和 δ 无论怎么分配，只要 O(3)=1.87，斜率就只能是 0.29。
物理含义：每多一步 chain draft（多验证 1 个位置 + 多算 1 次 draft），单轮开销就涨 29%。

---

## 3. τ 的几何结构

chain draft（topk=1）下，每步独立接受概率记作 p，则

```
τ(k) = 1 + p + p² + … + p^k = (1 - p^{k+1}) / (1 - p)     ……(3)
τ ≤ k + 1（最多全接受）
```

由 v1/v2 的 τ(3) 反解 p：

| | τ(3) | p |
|---|---|---|
| v1 | 2.090 | **0.572** |
| v2 | 2.268 | **0.626** |

数据翻倍让 p 涨了 **0.054**。

---

## 4. 把 (2)(3) 代回 (1)：加速比随 k 的完整曲线

```
S(k) = τ(k) / (1 + 0.29k)
```

| k | O(k) | τ(k) | **S(k)** |
|---|---|---|---|
| 1 | 1.29 | 1.626 | 1.260 |
| 2 | 1.58 | 2.017 | **1.277** ← 最优 |
| 3（当前） | 1.87 | 2.268 | 1.213 |
| 4 | 2.16 | 2.425 | 1.123 |
| 5 | 2.45 | 2.523 | 1.030 |
| 8 | 3.32 | 2.653 | 0.799 |

**在当前 draft 质量（p=0.626）下，把 k 从 3 调到任何值都无法超过 1.28x。**
加 draft 步数会让分母线性增长、分子却几何饱和——这是"越加越慢"的根源。

---

## 5. 2x 的充要条件

令 S(k) ≥ 2：

```
τ(k) ≥ 2 + 0.58k        ……(4)
```

逐个 k 检查（τ 的上限是 k+1）：

| k | 需要 τ | τ 的上限 | 可行性 |
|---|---|---|---|
| 2 | 3.16 | 3 | **数学上不可能** |
| 3 | 3.74 | 4 | 需 p = **0.955** |
| 5 | 4.90 | 6 | 需 p = **0.918** |
| 10 | 7.80 | 11 | 需 p = **0.928** |
| ∞ | 0.58k 无界 | 1/(1-p) 有界 | **p<1 时必然不可能** |

**结论（必要条件的严格形式）：**

> 在 O(k) = 1 + 0.29k 这个实测结构下，无论取多少 draft 步数，
> **2x 都要求每步接受概率 p ≥ 0.92**（最优情形在 k≈5~10）。

而实测 p = **0.626**。缺口 **0.29**，不是小数点后的问题。

---

## 6. 数据能不能把 p 从 0.63 推到 0.92？

用两轮实测做外推（唯一可用的数据点）：

```
p(21.75k) = 0.572
p(41.4k)  = 0.626        Δp = 0.054 / 每次数据翻倍
```

按这个斜率线性外推（已经是最乐观的假设，实际会饱和）：

```
需要翻倍次数 = (0.92 - 0.626) / 0.054 ≈ 5.4 次
需要数据量   = 41.4k × 2^5.4 ≈ 1.7M 条
```

而 ShareGPT 这个语料池去重后**总共只有 68,623 条**对话，其中结构有效的 44,009 条，
我们已经用掉 39,426 条。**理论天花板 68.6k ≈ 1.7M 的 4%**，差 25 倍以上。

这还没算 p 会随数据量饱和（边际收益递减）——真实曲线比线性外推更平。

---

## 7. 另一条路：压低 O 的斜率行不行？

要让 2x 在**当前 τ=2.268** 下成立，需要 O ≤ 1.134，即

```
O(3) = 1 + 3s ≤ 1.134  →  s ≤ 0.045
```

也就是说：**验证 4 个位置 + 3 步 draft，总代价只能比单 token 高 13%。**
但仅"验证 4 个位置"这一项，在 memory-bound 的 decode 里就已经 ≥ 10%，
再叠加 3 步 draft，s 不可能降到 0.045（实测 0.29，差 6 倍）。

要让 s 减半，draft 得小 3 倍以上——而更小的 draft 会让 p 掉得更快（第 6 节的反向）。

**这是同一枚硬币的两面：p 和 δ 此消彼长，EAGLE-3 的结构本身已经在这条曲线上取了近似最优点。**

---

## 8. 结论

1. **2x 不是"还没训够"，是结构性的。** 在当前"1 层 draft + 3 步 chain + topk=1"的配置下，即使 draft 完美（p=1），k 很大时 S 的上界也只有 1/0.29 ≈ 3.45；而在实测 p=0.63 时，S 的最优值就是 **1.28x**。

2. **实测 1.21x 已经接近这套结构的天花板**（1.28x），继续调 k 只会更差。

3. **要 2x，必须改结构而不是加数据**，可行方向：
   - **提高 τ 的上限**：tree draft（topk>1, num_draft_tokens 8~16），让一次验证覆盖更多候选分支。代价是 s 上升，需要重新算平衡点（很可能 s 涨得比 τ 快）。
   - **让 draft 几乎免费**：draft 量化到 fp8/int8、砍 draft 词表（32k→8k），把 δ 压到接近 0。这是唯一可能把 s 显著压低的路径，但要验证精度损失。
   - **换更小的 target**：target 越小，draft 的相对开销越大——方向相反，不成立。
   - **换更大的 target**：8B/32B 上 EAGLE-3 的 p 可以到 0.8+，τ 3~4，此时 2x 才有可能。但 4090 单卡放不下大 target 的 online 训练。

4. **本轮实验的可复现价值**：我们给出了 `O(k) = 1+0.29k` 这个可测的经验定律和 p 的反解方法，任何人换 config 后可以用同样两步（测 O、反解 p）预判自己的加速上限，不必先训 11 小时。
