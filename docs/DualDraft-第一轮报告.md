# EAGLE-3 Dual-Draft 实验报告（第一轮：负结果）

> 2026-11-04 · 基于 Qwen3-1.7B + 自训 41,405 条数据
> 对照组：已完成的 v2 基线（单网络，`0.8^i` 权重，τ=2.268）

---

## 0. 结论先行

| 问题 | 回答 |
|---|---|
| 把 draft 拆成 GtoA + AtoA 两个独立网络，有用吗？ | **没有** |
| 同口径验证集（step 40,000） | v2 **0.5026** vs dual **0.4851**（dual 低 0.0175） |
| 链式接受长度 τ | v2 **2.097** vs dual **2.067** |
| 参数量 | dual 是基线的 **1.85 倍**（可训练部分） |
| 训练集上的"领先" | 是**过拟合**，不是能力 |

**一句话**：用接近两倍的参数，在同等步数下换来了更差的泛化。原始假设（G→A 与 A→A 共享参数造成梯度干扰）**不被证据支持**。

---

## 1. 实验设计

### 1.1 架构（T1：共享 K/V）

| 组件 | GtoA（step 0） | AtoA（step ≥1） |
|---|---|---|
| 输入 | `cat(emb(x_t), fc(G_t))` → 4096 | `cat(emb(x_{t+i}), A_{i-1})` → 4096 |
| `fc` | ✅ (2048, 6144) | ❌ 不需要 |
| **k_proj / v_proj** | **共享同一组 Parameter** | **共享** |
| q_proj / o_proj / MLP / norms | 独立 | 独立 |
| lm_head | 独立 | 独立 |

**为什么共享 K/V**：EAGLE-3 的 draft 注意力只在自维护的 K/V 上。若两个网络各用一套投影，GtoA 写入 cache 的 K/V 与 AtoA 的 Q 属于**两个不同的基**，
注意力分数变成 `h_qᵀ (W_q^A)ᵀ W_k^G h_p` 这个跨基双线性型——数学合法，但**梯度会从这个乘积同时流回两个网络**，
等于把想消除的干扰原样引回来。而彻底分开 cache（各自只看到自己产生的位置）会让 GtoA 只看到约 30% 的历史。
**结论：完全参数独立与统一 cache 在数学上互斥**，本实验选择共享 K/V。

### 1.2 训练配置（与 v2 基线严格一致）

| 项 | 值 |
|---|---|
| 数据 / 验证集 | 41,405 / 2,179 |
| Epochs / Batch / LR | 3（实际跑到 60k 步）/ 1 / 1e-4 |
| TTT / MaxLen / Seed | 7 / 2048 / 42 |
| Target | Qwen3-1.7B 冻结（SGLang，mem-fraction 0.35） |
| **损失权重** | **step0 占 50%，其余 6 步按 0.8 衰减分 50%** |

> 基线是 `0.8^i` 衰减（step0 占 **25.3%**），本实验让 step0 提升到 **50%**（2 倍），总尺度缩放到与基线一致
> （`Σ0.8^i = 3.951`），保证梯度量级不变。

### 1.3 实现验证（阶段 A）

| 检查 | 结果 |
|---|---|
| k_proj/v_proj 共享同一对象 | ✅ |
| q_proj/MLP/lm_head 独立 | ✅ |
| 7 步前向无 NaN、cache 累积 7 层 | ✅ |
| checkpoint 两套权重完整保存 | ✅ 27 个键，10+10+2 |
| **梯度隔离（关键）** | ⚠️ **非对称** |

**梯度隔离测试的结果与预期不同**：

```
step0 的 loss → GtoA mlp 梯度非零 ✅
step0 的 loss → AtoA mlp 梯度 = None（完全隔离）✅
step1 的 loss → GtoA mlp 梯度 = 2.7e7（有！）❌ 预期之外
```

原因：A₁ 是 GtoA 的输出、又是 AtoA 的输入，所以**后续步骤的 loss 会通过状态链反传回 GtoA**。
也就是说"两个网络互不影响"**只成立一半**：AtoA 被隔离，GtoA 仍被所有步骤塑造。
这从一开始就削弱了"消除梯度干扰"的前提。

## 2. 结果

### 2.1 同口径对比（同一 eval 集、同一代码，两个检查点）

| step | 模型 | mean_acc | **τ(链式)** | acc_0 | acc_6 |
|---|---|---|---|---|---|
| 40,000 | v2 基线 | **0.5026** | **2.097** | 0.604 | 0.446 |
| 40,000 | dual-draft | 0.4851 | 2.067 | 0.603 | 0.429 |
| 40,000 | **Δ** | **−0.0175** | **−0.030** | −0.001 | −0.017 |
| 60,000 | v2 基线 | **0.5616** | **2.257** | 0.649 | 0.509 |
| 60,000 | dual-draft | 0.5462 | 2.230 | 0.649 | 0.493 |
| 60,000 | **Δ** | **−0.0154** | **−0.027** | 0.000 | −0.016 |

**两个独立检查点给出了同样的结论**（gap −0.015 ~ −0.018），这不是噪声。

**最关键的一行**：`acc_0` 几乎完全相同（0.603 vs 0.604）。
GtoA 专门为第一步训练、且拿到 50% 的权重，结果第一步的接受率**和共享网络一模一样**。

### 2.2 训练集上的"领先"是过拟合

| | 训练 acc（40–45k） | 验证 acc（40k） | **间隙** |
|---|---|---|---|
| v2 | 0.505 | 0.503 | **+0.002** |
| dual | 0.523 | 0.485 | **+0.038** |

v2 的训练/验证几乎无间隙（0.002），dual 有 0.038 的间隙。
**dual 多出来的参数在记忆训练数据，没有学到可迁移的模式。**

### 2.3 dual 的完整 eval 曲线

| step | 10k | 20k | 30k | 40k | 50k | 60k |
|---|---|---|---|---|---|---|
| mean_acc | 0.360 | 0.410 | 0.441 | 0.485 | 0.519 | 0.546 |
| **τ** | 1.73 | 1.86 | 1.95 | 2.067 | 2.154 | **2.230** |

每千步的增益约 0.0031（acc），与 v2 的 0.0027 接近 → **两条曲线会收敛到同一处**，dual 起点低、斜率相同。

## 3. 为什么失败：四条原因

### ① 解耦本身不成立（结构性原因）

如 §1.3，GtoA 的梯度仍从所有后续步骤回流。
所谓"两个任务互相干扰"在数据流上并不存在——**它们通过状态 A₁ 强耦合**，只是参数不再共享。
把一个耦合系统拆成两半，耦合不会消失，只是从"参数内"转到"参数间"。

### ② EAGLE-3 的单层 draft 本就容量充足

draft 只有 1 层、137M 参数，但要学的映射相对简单（`cat(emb, hidden)` → 下一 token 分布）。
EAGLE-3 用一套参数同时拟合两种输入分布，**本身并不吃力**——这也解释了为什么 acc_0 完全没有提升。
参数量翻倍只带来了过拟合。

### ③ 共享 K/V 让"解耦"名不副实

为了 cache 兼容而共享 k_proj/v_proj，意味着两个网络上唯一"跨任务耦合"的路径恰恰保留了下来。
但从 §1.1 的分析看，这又是不可避免的——**除非接受上下文被切碎**。

### ④ 我们自己的假设也在收缩

设计阶段就已经发现：先验工作（HCSpec ACL'26、Gumiho ICML'25、CORAL ACL'25、Jakiro 2025）分别占位了
"位置专门化模块"、"早重后轻"、"多步输入不一致"、"解耦多头"。本实验的独立空间只剩"完全参数分离"这一刀，
而这一刀在工程上又与 cache 统一互斥。**能动的空间本就很小。**

## 4. 这个负结果的价值

### 4.1 可迁移的结论

1. **"拆网络"不是 EAGLE 类 draft 的有效改进方向**——至少对 1.7B 这个尺度、1 层 draft、41k 数据不成立。
   这条对后来者有直接的节省价值。
2. **KV cache 不可兼得定理**（§1.1）：完全参数独立 ⇔ 上下文被切碎。这是一个结构性结论，与具体模型无关。
3. **解耦是不对称的**：共享状态的链式结构下，上游网络永远被下游 loss 塑造。
4. **诊断方法**：`train-eval gap` 是区分"能力提升"与"过拟合"的廉价判据，比只看训练曲线可靠。

### 4.2 方法论教训

**在投入 11 小时训练前，先用 30 分钟做梯度隔离测试。**
我们在阶段 A 就发现了"GtoA 仍被下游 loss 训练"这一事实，但当时只当作"有趣的观察"，
没有据此下调预期——如果当时就此停止，可以省下约 ¥25 和 3 小时。

## 6. 后续（第二轮）

按"严格回到基线权重"再测一次，单独隔离架构变量：

| 组 | 权重 | 目的 |
|---|---|---|
| **R2-0.8** | `0.8^i`（与基线完全相同） | **唯一变量 = 架构** |
| **R2-0.7** | `0.7^i`（更陡，step0 占 32.7%） | 衰减率是否敏感 |

两者都与 v2 在 step 60,000 同口径对比。预期：若 R2-0.8 ≈ v2，则彻底确认架构无效；
若 R2-0.7 明显不同，则说明**权重分布**比架构更值得调。
