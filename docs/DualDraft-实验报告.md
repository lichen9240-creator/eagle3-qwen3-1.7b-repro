# EAGLE-3 Dual-Draft 实验报告

> 2026-11-04 · Qwen3-1.7B · 41,405 条训练数据 / 2,179 条验证集
> 全部对比在同一 eval 流程、同一验证集上完成，报告的是**链式接受长度 τ**
> （`τ = 1 + a₁ + a₁a₂ + a₁a₂a₃`，对应服务时的 k=3）

---

## 0. 一句话结论

**把 draft 拆成 GtoA + AtoA 两个独立网络是亏的（τ −0.075）；但把注意力放在"损失衰减率"上是赚的（+0.105）。
两者叠加后净赚 +0.030，其中真正的功臣是衰减率，不是架构。**

## 2. 架构设计（T1：共享 K/V）

| 组件 | GtoA（step 0） | AtoA（step ≥1） |
|---|---|---|
| 输入 | `cat(emb(x_t), fc(G_t))` | `cat(emb(x_{t+i}), A_{i-1})` |
| `fc` | ✅ (2048,6144) | ❌ |
| **k_proj / v_proj** | **共享同一组 Parameter** | **共享** |
| q/o/MLP/norms/lm_head | 独立 | 独立 |

### 为什么必须共享 K/V

EAGLE-3 的 draft 注意力只在自己维护的 K/V 上。若两网络各用一套投影，
GtoA 写入 cache 的 K/V 与 AtoA 的 Q 属于两个不同的基：

```
s(q,p) = h_qᵀ (W_q^A)ᵀ W_k^G h_p
```

这是一个合法的双线性型，但**梯度会从 `(W_q^A)ᵀW_k^G` 同时流回两个网络**——
想消除的干扰原样回来了。而彻底分开 cache（各自只看自己产生的位置），
GtoA 只能看到约 30% 的历史。

> **结论：完全参数独立与统一 cache 在数学上互斥。** 这是本实验的结构性发现之一。

---

## 3. 实现验证：一个被忽略的关键事实

阶段 A 的梯度隔离测试：

```
step0 的 loss → GtoA 有梯度 ✅
step0 的 loss → AtoA 完全无梯度 ✅
step1 的 loss → GtoA 有梯度（2.7e7）❌ 预期外
```

原因：A₁ 既是 GtoA 的输出、又是 AtoA 的输入，**后续步骤的 loss 会沿状态链反传回 GtoA**。

> **"解耦"是不对称的：AtoA 被隔离，GtoA 仍被所有步骤塑造。**

这一点在训练开始前就测出来了，但当时没有据此下调预期——方法论上的教训见 §7。

## 4. 结果分解

同一步数（40k）下：

```
v2 基线（单网络, 0.8^i）        τ = 2.097
双网络 + 0.8^i                  τ = 2.022     → 架构效应 = −0.075
双网络 + 0.7^i                  τ = 2.127     → 衰减效应 = +0.105
```

**架构本身是有害的，0.7 衰减把它拉回来还赚了 0.03。**

### 训练集"领先"是过拟合

| | 训练 acc | 验证 acc | 间隙 |
|---|---|---|---|
| v2 | 0.505 | 0.503 | +0.002 |
| 双网络 | 0.523 | 0.485 | **+0.038** |

双网络多出的 85% 参数在记忆训练数据，没有学到可迁移的模式。

## 5. 损失衰减率：社区现状与我们的测量

### 5.1 各开源实现的实际设置

| 实现 | 代码位置 | 公式 | step0 占比 |
|---|---|---|---|
| **EAGLE-3 官方**（SafeAILab） | `eagle/traineagle3/main.py:284` | `0.8 ** i` | 25.3% |
| **SpecForge**（sgl-project） | `scripts/train_eagle3.py:655` | `0.8 ** i` | 25.3% |
| **Speculators**（vLLM 官方） | `schema.py:325` | `ttt_step_loss_decay = 1.0` | **14.3%（不衰减）** |
| DFlash 系列（Speculators） | `losses/utils.py:44` | `exp(-(pos-1)/4.0)` | 另一种形式 |
| EAGLE-2 官方 | `eagle/train/main.py` | 无 TTT，无逐位置权重 | — |

原文：

```python
# SafeAILab/EAGLE eagle/traineagle3/main.py L284
ploss_weight = [0.8 ** i for i in range(len(plosses))]

# vllm-project/speculators schema.py L325
ttt_step_loss_decay: float = Field(
    default=1.0,
    description="Multiplicative loss weight decay applied per TTT step "
                "(1.0 = weight every step equally).",
)
```

**两套主流实现互相矛盾。**

### 5.2 但真正的变量是「step0 占比」，它由衰减率 × TTT 长度共同决定

| 配置 | step0 占比 | 前 3 步累计 | 末步占比 |
|---|---|---|---|
| EAGLE 0.8^i, TTT=7 | 25.3% | 61.7% | 6.6% |
| Speculators 1.0, TTT=3 | **33.3%** | 100% | 33.3% |
| Speculators 1.0, TTT=7 | 14.3% | 42.9% | 14.3% |
| **我们的 0.7^i, TTT=7** | **32.7%** | 71.6% | 3.8% |

**EAGLE（25.3%）与 Speculators（33.3%）其实都落在 25–33% 这个带里**，
而我们实测的最优点 **32.7% 更接近 Speculators 的默认**，说明 EAGLE 的 0.8 偏保守。

### 5.3 倒 U 型

| step0 占比 | 来源 | τ@40k |
|---|---|---|
| 25.3% | EAGLE 官方 | 2.097 |
| **32.7%** | **本实验** | **2.127** ✅ |
| 50.0% | 本实验（0.5/0.5） | 2.067 |

过少（25%）和过多（50%）都更差，峰值在 33% 附近。

### 5.4 TTT 长度的两个影响

1. **训练成本**：TTT=7 每样本 7 次 draft 前向，TTT=3 只要 3 次 → **快 2.3 倍**
2. **浪费**：训练 TTT=7 但服务 k=3 时，0.8^i 有 **25.3%** 的权重花在推理用不到的深度上（0.7^i 为 17.1%）

> **训练深度应当匹配推理深度。** 服务 k=3 时 TTT=3 既省算力又不浪费权重。

## 6. 结论与建议

1. **不要拆网络**（至少对 1.7B / 1 层 draft / 41k 数据）。架构效应是 −0.075。
2. **要调衰减率**。`0.7^i` 相对 `0.8^i` 带来 +0.105（同架构内）。
3. **先看 step0 占比，而不是衰减率本身**。33% 左右是一个合理的起点；
   如果你用 TTT=3，直接 `decay=1.0` 就是 33.3%。
4. **TTT 匹配服务深度**，能省 2.3 倍训练算力。
5. **判据用 `train-eval gap`**：训练集涨、验证集不涨就是过拟合，比只看训练曲线可靠。

## 7. 方法论教训

**在投入 11 小时训练前，先花 30 分钟做梯度隔离测试。**
本实验在阶段 A 就发现"GtoA 仍被下游 loss 训练"，这是对核心假设的直接反证，
但当时只当作"有趣的观察"，没有据此下调预期。

另外：**同一份数据、同一张卡、同一 seed 的对照，比多跑几个模型变体更能回答问题。**
本次真正有信息量的不是 d07 赢了多少，而是 d08（唯一变量 = 架构）**输了 0.075**。

## 8. 操作事故记录（供复现者避坑）

| 事件 | 根因 | 修复 |
|---|---|---|
| 训练在 27k 步中断 | AutoDL 余额耗尽自动关机 | 充值后 `--resume`，checkpoint 每 5000 步 |
| 监控失明 7 小时 | 健康检查依赖 SSH，关机即断且不重连 | 改走 AutoDL API + SSH 自动重连 |
| 发散误报 | 用单 batch 的 loss 判定 | 改为 1000 步窗口均值 |
| **d08 在 25k 崩溃** | **磁盘写满，checkpoint 写入被截断**（`inline_container.cc: unexpected pos`） | 清理 95GB→19GB；save-interval 改 10000 |
| metrics.jsonl step 回退 | resume 从更早的 step 重写 | 分析脚本按追加顺序取当前、按 step 去重统计 |

> 每个 checkpoint 是 2.5GB（权重 522MB + optimizer 状态 2GB）。
> 长时间多组训练时，**磁盘是比显存更容易忽略的瓶颈**。
