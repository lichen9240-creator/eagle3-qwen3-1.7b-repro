# Qwen3-1.7B EAGLE-3

EAGLE-3 draft head for **Qwen/Qwen3-1.7B**, trained by [Lichen-Creator](https://huggingface.co/Lichen-Creator).
A single-layer `LlamaForCausalLMEagle3` with a 32k draft vocabulary, trained online on 41,405 conversations
regenerated by Qwen3-1.7B itself.

**Verified on SGLang 0.5.9 and vLLM 0.11.2.** SGLang loads it as `LlamaForCausalLMEagle3`;
vLLM logs `Detected EAGLE model without its own embed_tokens ... Sharing target model embedding weights`.
No conversion required.

- 📄 Full experiment report & code: [lichen9240-creator/eagle3-qwen3-1.7b-repro](https://github.com/lichen9240-creator/eagle3-qwen3-1.7b-repro)

---

## 🌟 Key Features

- **Ready to deploy**: standard EAGLE-3 checkpoint (`d2t` / `t2d` included), loads directly in SGLang 0.5.9
  and vLLM 0.11.2 — both verified
- **No proprietary embedding**: shares the target model's `embed_tokens`, only 274 MB on disk
- **1.879x end-to-end speedup** with vLLM on a consumer RTX 4080 SUPER (1024-token outputs, C=1),
  acceptance 2.33
- **Ahead of the reference release on the same hardware**: 282.4 vs 264.7 tok/s (1024 tok, vLLM),
  and acceptance 2.175 vs 2.111 (SGLang, RTX 4080S)
- Loads as `LlamaForCausalLMEagle3` in SGLang and as `Detected EAGLE model without its own embed_tokens`
  in vLLM, no conversion needed

## 💼 Model Overview

| Property | Value |
|---|---|
| Target model | `Qwen/Qwen3-1.7B` (bf16) |
| Draft architecture | 1 layer, hidden 2048, 16 heads / 8 KV heads, head_dim 128, intermediate 6144 |
| Draft vocabulary | 32,000 (`draft_vocab_size`), mapped to 151,936 via `d2t` / `t2d` |
| Parameters on disk | 274 MB (13 tensors + `d2t` / `t2d`) |
| dtype | bfloat16 |
| Embedding | shared with the target (`tie_word_embeddings` handled by the runtime) |
| License | Apache-2.0 |

The config mirrors the official [`qwen3-8b-eagle3.json`](https://github.com/sgl-project/SpecForge/blob/main/configs/qwen3-8b-eagle3.json)
field-for-field, with only the width fields scaled to the 1.7B target (hidden 4096→2048, heads 32→16,
intermediate 12288→6144, window layers 36→28).

## 🛎️ How to Use

### 1. Install

```bash
pip install "sglang[all]==0.5.9"        # or: pip install vllm==0.11.2
pip install "transformers==4.57.1"
```

### 2. SGLang

```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-1.7B \
  --speculative-algorithm EAGLE3 \
  --speculative-draft-model-path Lichen-Creator/Qwen3-1.7B_eagle3 \
  --speculative-num-steps 3 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4 \
  --dtype bfloat16 --mem-fraction-static 0.55
```

Expected log line:

```
Load weight end. elapsed=0.06 s, type=LlamaForCausalLMEagle3, dtype=torch.bfloat16
```

> `--speculative-draft-model-path` accepts a local directory or a Hub repo id.

### 3. vLLM

```bash
python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen3-1.7B \
  --speculative-config '{"model": "Lichen-Creator/Qwen3-1.7B_eagle3", "num_speculative_tokens": 2}' \
  --dtype bfloat16 --gpu-memory-utilization 0.55
```

Expected log lines:

```
Detected EAGLE model without its own embed_tokens in the checkpoint. Sharing target model's embed_tokens.
Detected EAGLE model with distinct lm_head weights. Keeping separate lm_head weights.
```

### 4. Going deeper: tree draft

With SGLang, raising the branching factor turns the chain into a tree verified in a single target forward:

```bash
--speculative-num-steps 3 --speculative-eagle-topk 2 --speculative-num-draft-tokens 8
```

Measured: acceptance 2.175 → **2.500**, speedup 1.219x → **1.324x** (RTX 4080 SUPER, C=1).

## 📈 Benchmark

Protocol: 90 fixed prompts (30 chat / 30 math / 30 code), greedy (`temperature=0, top_k=1, top_p=1.0,
ignore_eos=True`), identical sampling for baseline and EAGLE.

### SGLang 0.5.9 — RTX 4090 48GB

| Concurrency | baseline tok/s | EAGLE tok/s | Speedup | Acceptance |
|---|---|---|---|---|
| C=1 | 234.0 | 283.6 | **1.212x** | 2.268 |
| C=4 | 791.1 | 954.8 | 1.207x | 2.255 |
| C=8 | 1493.0 | 1777.4 | 1.190x | 2.256 |

### vLLM 0.11.2 — RTX 4080 SUPER 32GB

`--speculative-config '{"model": "Lichen-Creator/Qwen3-1.7B_eagle3", "num_speculative_tokens": 2}'`

| Output length | baseline tok/s | **this model** | Speedup | Acceptance |
|---|---|---|---|---|
| 128 tokens, C=1 | 152.3 | **242.1** | **1.590x** | 2.33 |
| 128 tokens, C=4 | 565.0 | **852.8** | **1.509x** | 2.33 |
| 1024 tokens, C=1 | 150.3 | **282.4** | **1.879x** | 2.33 |

### Versus the reference release

Same card (4080S), same engine, same benchmark, each with its own weights:

| Engine | Metric | **this model** | AngelSlim/Qwen3-1.7B_eagle3 |
|---|---|---|---|
| SGLang 0.5.9 | acceptance (k=3) | **2.175** | 2.111 |
| SGLang 0.5.9 | speedup | **1.219x** | 1.149x |
| vLLM 0.11.2 | throughput, 1024 tok | **282.4 tok/s** | 264.7 tok/s |
| vLLM 0.11.2 | speedup, 1024 tok | **1.879x** | 1.761x |

**+6.7% throughput over the reference checkpoint under vLLM**, +5.7% under SGLang.

> The comparison against AngelSlim's *published* 1.687x is a **cross-hardware, cross-evaluation-set**
> comparison (they report a GSM8K/Alpaca/HumanEval/MT-bench average on an H20; we use 90 fixed prompts on
> a 4080S), so treat it as a magnitude reference, not a head-to-head win. The same-hardware numbers above
> are the fair comparison.

## 🔧 Training

| Item | Value |
|---|---|
| Framework | [SpecForge](https://github.com/sgl-project/SpecForge) @ `961ca7c` |
| Data | ShareGPT (deduplicated + structure-filtered) 30,149 + UltraChat 13,435 = **43,584** conversations |
| Data generation | Regenerated by Qwen3-1.7B itself (`temperature 0.8, top_p 0.95, top_k 20, max 512`), then zero-loss / `max_length=2048` filtered |
| Split | 95/5 with seed 42 → train 41,405 / eval 2,179 |
| Schedule | 3 epochs, batch size 1, lr 1e-4, `ttt_length 7`, seed 42, `attention_backend sdpa` |
| Steps / wall time | 124,215 steps / ~11 hours on one RTX 4090 48GB (3.2 steps/s) |
| Convergence | loss 3.73 → 0.60; teacher-forcing accuracy 0.03 → ~0.70 |

## ⚠️ Limitations

1. **Outputs are not bit-identical to the target.** On 10 greedy prompts × 64 tokens, 5 differ from the
   baseline — but the EAGLE server is deterministic run-to-run (10/10 identical). The divergence comes from
   bf16 GEMM shapes differing between batched verification and single-token decode, flipping the argmax at
   near-ties. This is inherent to bf16 speculative decoding, not specific to this checkpoint.
2. **The `d2t` / `t2d` mapping is model-specific.** It is fixed by training; do not mix it with another
   Qwen3-1.7B EAGLE-3 draft.
3. **Small evaluation set.** 90 fixed prompts, 128 output tokens; long-context and production traffic are
   not covered.
4. **English-dominant data.** Chinese quality was not evaluated separately.
