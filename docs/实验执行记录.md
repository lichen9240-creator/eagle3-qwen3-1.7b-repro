## 2. 数据管线偏差（偏差 #1）

手册假设 ShareGPT 120k 条可直接抽样 30k。实际数据有两个问题，均在**候选池**阶段修正，不改样本量/切分/种子：

1. **重复 id**：120,675 → 68,623（丢弃 52,052 条重复 id）。
2. **结构无效**：68,623 中 **35.9%（24,611 条）以 assistant 开头**，`regenerate_train_data.py` 直接报
   `Data starts with an assistant message`（G2 首轮 132 条里 44 条失败）。若失败即丢弃，train 只剩
   18,398，**低于手册 G3 的 20,000 门槛**——方案内部自相矛盾。
   → 在候选池内先剔除「以 user 开头、user/assistant 严格交替、以 assistant 结尾」以外的对话：68,623 → **44,009**。

丢弃原因分布（互斥）：

```
ok                       44,009   64.1%
starts_with_assistant    24,611   35.9%
ends_with_user                3    0.0%
```

之后照手册：`seed=42` 全量洗牌 → 30,000 → 前 1,500 eval，其余 28,500 train。

## 3. 环境适配（构建问题，非方案偏差）

镜像自带 CUDA 11.8 的 nvcc 与 gcc 9，无法编译 sglang 的 C++20 JIT 内核：

1. `nvidia-cuda-nvcc-cu12`(pip) 12.x 只含 `ptxas`；conda nvidia 频道的 `cuda-nvcc` 是 17KB 占位包 → 均不可用。
2. 从 NVIDIA redistrib 拉组件包：`cuda_nvcc`(79MB) + `cuda_cudart` + `cuda_cccl` → `$ROOT/envs/cuda128`。
3. `apt install gcc-10 g++-10`（C++20 `<concepts>`），nvcc `-ccbin` 指向它。
4. `tvm_ffi` JIT 链接固定 `$CUDA_HOME/lib64` → 建 `lib64 -> lib` 软链。

## 5. 代码/参数级偏差（逐条登记）

### 5.1 G5 断言修正（手册笔误）

手册断言：
```python
assert tuple(x["hidden_state"].shape[-2:]) == (2048, 2048)
assert tuple(x["aux_hidden_state"].shape[-2:]) == (2048, 6144)
```
实际 batch=1、**变长序列**（不 padding），形状是 `(1, L, 2048)` / `(1, L, 6144)`，
`shape[-2:]` 取到的是 `(L, 2048)`，只有 L=2048 时才成立。
→ 改为按语义校验：`h.shape == (1,L,2048)`、`a.shape == (1,L,6144)`、`a[-1] == 3*h[-1]`、
mask 与 ids 同形且和 >0、全有限。10/10 通过，`HIDDEN_SCHEMA_OK`。

### 5.2 训练 attention backend：flex_attention → sdpa（硬件限制）

手册固定 `--attention-backend flex_attention`。本机实测 **必定失败**：

```
torch._inductor.exc.InductorError: RuntimeError: No valid triton configs.
OutOfMemoryError: out of resource: triton_tem_fused_0
Required: 106496  Hardware limit: 101376
```

draft 自注意力的 flex_attention Triton 模板需要 104KB 共享内存，sm_89 单 block 上限 99KB，
inductor 试遍所有配置均放不下（与显存无关，是 shared memory）。
→ 改用 SpecForge 原生支持的 `--attention-backend sdpa`（也是其代码默认值），数学等价，仅 kernel 不同。
**这是本实验唯一的"非数据"参数改动**，原因记录在此。

### 5.3 训练速率实测

- 1k 训练：0.39 s/步
- 正式训练：**0.29 s/步**（3.47 it/s，dataloader 4 workers）
- 65,250 步 → 约 5.2 小时

## 7. 基础设施修正（与方案无关）

`rc.py` 原先所有远端脚本都写到同一个 `/tmp/_dsh_step.sh`，而 bash 按偏移增量读脚本：
后续调用覆盖该文件会导致**正在运行的后台脚本读到错位内容而静默退出**。
表现为 G3 驱动脚本在 train regen 结束后丢失了 eval 步骤。已改为每次唯一文件名，
并单独补跑了缺失的 eval（1,500 条，0 失败）。
